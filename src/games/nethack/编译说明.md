# NetHack 5.0.0 TCMIPS 移植：编译说明

本代码从 NetHack 5.0.0 移植到 TCMIPS 平台。本文说明：

- 源码由哪些部分组成
- 如何编译成设备 `.tcm` 镜像
- 如何在本机编译调试版
- 各源码文件的角色、关键补丁与构建排障

---

## 一、代码结构

```
src/games/nethack/
├── core/                  NetHack 游戏核心(约 130 个 .c，vendor 原版)
├── tty/                   tty 窗口接口(wintty.c / topl.c / getline.c)
├── sys/                   Unix 系统层替代(random.c / posixregex.c)
├── lua/                   vendor 的 Lua 5.4.8 运行时(32 个 .c)
├── include/               vendor 头文件(unixconf.h 已打 TCMIPS 补丁)
│
├── tcm_main.c             入口 main(替代 sys/unix/unixmain.c)
├── tcm_vterm.c            虚拟终端 + 直写 VRAM 渲染(30×80 字符)
├── tcm_termcap.c          渲染后端(替代 termcap.c 的 cmov/xputc/清屏)
├── tcm_fs.c               设备 RAM 文件系统 + POSIX 覆盖层
├── tcm_kbd.c              键盘驱动与按键映射
├── tcm_dirent.c           dirent 族 API 桩
├── tcm_hooks.c            平台钩子(时钟/锁文件/身份/随机种子等)
├── nhfont.c               8x16 像素字体位图
├── tcm_console_sim.c      宿主 VRAM 仿真器(仅宿主构建)
└── tcm_port.h             平台宏改名层 + 声明(接线核心!)
```

数据资源在 `asset/nethack/`：

```
asset/nethack/
├── dat/           NetHack 运行时数据(145 个文件：全部 .lua 关卡与地牢描述、
│                  oracles、rumors、epitaph、symbols、.nethackrc…)
├── nhdata.h       生成的头文件：嵌入文件表声明
└── nhdata.cpp     生成的字节数组(已提交，构建直接用)
```

## 二、设备构建(.tcm 镜像)

### 2.1 工具链

| 组件 | 路径 | 说明 |
|---|---|---|
| C/C++ 编译器 | `toolchains/llvm/bin/clang{,++}` | 目标 `mipsel-unknow-elf` |
| 链接器 | `toolchains/llvm/bin/llvm-link-tcmips` | 把 `.bc` 位码库链接为 `.tcm` ELF 镜像 |
| sysroot | `toolchains/sysroot/` | picolibc；**只能用于 Release**(无 debug 变体) |
| CMake 工具链 | `toolchains/cmake/tcmips.toolchain.cmake` | 根 `CMakeLists.txt` 自动引用 |

### 2.2 两段式编译

**编译段**：clang 加 `-emit-llvm`，每个源文件产出位码目标(CMake 里后缀为 `.obj`，实际是 `.bc`)。统一旗标：

```
--target=mipsel-unknow-elf  -msoft-float -march=mips32r2 -mabi=32 -mno-abicalls
-mllvm -mno-check-zero-division -emit-llvm
-D_FORTIFY_SOURCE=0 -D_DEFAULT_SOURCE=1 -D_GNU_SOURCE=1
-fno-use-cxa-atexit -fno-register-global-dtors-with-atexit -funroll-loops
-Wall -Wextra -Werror=implicit-function-declaration -Werror=implicit-int -Werror=return-type
```

**链接段**：`llvm-link-tcmips -tcm-elf` 把全部 `.bc` 与 picolibc 位码链接成 `.tcm` 镜像。

### 2.3 构建命令

用 CLion 打开仓库根目录(自动拾取 `tcmips.toolchain.cmake`)，选 **Release** 配置，
构建 `tcmips_nethack`。或命令行(与 README 一致)：

```bash
cmake -G Ninja -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target tcmips_nethack
```

产物：`build/tcmips_nethack.tcm`(约 7MB)，烧录到设备运行。

### 2.4 目标组成与专属旗标

`tcmips_nethack` 由根 `CMakeLists.txt` 列出：

- `core/*.c`(全部)、`tty/*.c`(wintty/topl/getline)、`sys/*.c`(random/posixregex)
- `lua/*.c`(全部 32 个，**排除** lua.c / luac.c / onelua.c)
- `tcm_*.c + nhfont.c`(平台层)
- `asset/nethack/nhdata.cpp`(嵌入数据，按 C++ 编译)

专属定义与选项：

```
-DTCMIPS_PORT -DGCC_UMINUS_NOSTATICUNUSED -DNO_SIGNAL -DNOMAIL -DNO_TERMCAP_HEADERS
-fsigned-char -fno-omit-frame-pointer -fno-jump-tables
```

特殊：`lua/lvm.c` 单独强制 `-O1`(computed-goto 禁用后正常 switch 版用 O3 在
4.6MHz 上可能过慢，O1 已验证 VMs 正常)。

## 三、本机编译(宿主调试版)

宿主构建不链接 `tcm_fs.c`，文件操作走 glibc 真文件系统；渲染走
`tcm_console_sim.c`(mmap 仿真 0x03C00000 VRAM，可截图)。渲染/逻辑调试极快，
但**不能复现设备文件层的 bug**。

### 3.1 普通宿主版(编译命令示例)

```bash
gcc -O1 -g -std=gnu99 \
    -DTCM_HOST -DTCMIPS_PORT -DNO_SIGNAL -DNOMAIL \
    -DNO_TERMCAP_HEADERS -DGCC_UMINUS_NOSTATICUNUSED \
    -Isrc/games/nethack/include -Isrc/games/nethack/lua \
    -Isrc/games/nethack -Iasset/nethack \
    -Wno-implicit-function-declaration -Wno-format-security \
    -o nethack \
    $(src/games/nethack/core/*.c tty/*.c sys/*.c lua/*.c) \
    src/games/nethack/tcm_main.c tcm_vterm.c tcm_termcap.c \
    tcm_kbd.c tcm_dirent.c nhfont.c tcm_hooks.c tcm_console_sim.c \
    asset/nethack/nhdata.cpp -lm
```

要点：

- 排除 `lua/lua.c`、`lua/luac.c`、`lua/onelua.c`；**不含** `tcm_fs.c`
- 运行时从 `asset/nethack/dat/` 下启动(程序用相对路径找数据)
- 截图钩子：stdin 中发 `\x01` + 文件名，会在进程 cwd 的 `shots/` 输出 PPM

### 3.2 宿主 RAM-fs 版(编译命令示例)

在 3.1 基础上：

- 追加编译 `tcm_fs.c`
- 追加 `-DTCM_FS_HOST`

此时 `tcm_port.h` 的 POSIX 宏改名层在宿主同样生效，游戏的
open/creat/unlink/read 等**全部走 RAM 文件层**——设备上的关卡锁文件、
检查点等问题可在宿主秒级复现并用 gdb 直接查栈。

## 四、嵌入数据如何编译进镜像

`asset/nethack/nhdata.cpp` 由打包脚本生成：扫描 `asset/nethack/dat/` 下全部
文件，输出嵌入字节数组与文件表：

```bash
# 扫描 asset/nethack/dat/ → 重写 nhdata.h / nhdata.cpp
<打包脚本> asset/nethack/dat/ asset/nethack/nhdata
```

- 生成的 `nhdata.{h,cpp}` **已提交到仓库**，正常构建无需重跑
- 仅在增删/修改 `dat/` 内容后才需要重新生成
- 设备端 `tcm_main.c` 启动早期调 `tcm_fs.c::tcm_embed_init()` 把整张表拷贝进
  堆 RAM；之后所有嵌入文件(含全部 .lua)通过 `tcm_fs_open` 按文件名打开

## 五、平台层文件职责与编译条件

| 文件 | 设备 | 宿主 | 宿主 RAM-fs | 职责 |
|---|---|---|---|---|
| `tcm_main.c` | ✓ | ✓ | ✓ | main()：控制台/嵌入表初始化 → 锁文件 → 新游戏 → moveloop |
| `tcm_vterm.c` | ✓ | ✓ | ✓ | 30×80 虚拟终端、dirty 行增量刷新、直写 0x03C00000(640×480 RGB332)；宿主走仿真缓冲 |
| `tcm_termcap.c` | ✓ | ✓ | ✓ | cmov/xputc/属性/清屏 → tcm_vterm |
| `tcm_fs.c` | ✓ | ✗ | ✓ | RAM 文件系统 + 嵌入文件表 + getenv/getpid 覆盖；文件尾有强符号 POSIX 包装(仅设备) |
| `tcm_kbd.c` | ✓ | ✓ | ✓ | tcm_getch：方向键=1-4→hjkl，Backspace=ESC，Enter/Del/Tab；宿主读 stdin |
| `tcm_hooks.c` | ✓ | ✓ | ✓ | clock/napms/随机/regularize/getlock(创建 1lock.0 写 pid) |
| `tcm_dirent.c` | ✓ | ✓ | ✓ | dirent 桩 |
| `nhfont.c` | ✓ | ✓ | ✓ | 8x16 字体位图 |
| `tcm_console_sim.c` | ✗ | ✓ | ✓ | 宿主仿真器：mmap 仿真 VRAM + 截图/文本导出 |

`tcm_port.h`(三个构建都 include 的接线核心)：

- `#if !defined(TCM_HOST) || defined(TCM_FS_HOST)` 时把 POSIX 文件调用
  宏改名到 `tcm_fs_*`：

  ```
  open/read/write/close/lseek/unlink/link/creat/open64/creat64/openat/openat64
  chmod/stat/fstat/isatty/access/rename/fcntl/getcwd
  ```

  原因：设备上 picolibc 的 libc.bc 对裸符号绑定优先，只有改调用点名字才能
  保证游戏代码走我们的 RAM 文件层。
- 声明 `tcm_fs_*` 与 `tcm_vterm_*`、`tcm_getch`、`tcm_wall_ms` 等。

## 六、vendor 源码上的关键补丁(编译期由宏区分)

| 文件 | 补丁 | 原因 |
|---|---|---|
| `include/config.h` | 注释掉 `NHL_SANDBOX` | sandbox 版 openlibs 的 DROPIF 表初始化在设备上挂死 |
| `include/unixconf.h` | TCMIPS_PORT 块：include tcm_port.h、`tgetch→tcm_getch`、msleep/Rand 处理 | 平台接线 |
| `include/wintty.h` | TCMIPS_PORT 下 `putchar(x)→xputc(x)`、`puts(s)→xputs(s)` | 黑屏根因：字符必须走 vterm |
| `core/nhlua.c` | 设备分支：nhl_loadlua 用 `tcm_fs_open+read` 读 .lua 进内存再 `luaL_loadbuffer`；Lua 库只开安全子集(排除 package/loadlib) | 设备 stdio 读不了嵌入文件 |
| `lua/lvm.c` | `__mips__` 下禁用 computed-goto；CMake 再强制 -O1 | 后端生成的跳转表损坏，VM 首条指令跳飞 |
| `core/sfstruct.c` | TCMIPS_PORT 禁用 `USE_BUFFERING` | `fdopen()` 在合成 fd 上失败，数据进不了 RAM 层 |
| `core/save.c` | `savestateinlock()` 开头加 `something_worth_saving` 守卫 | 新游戏首次检查点误读 1lock.0 → TRICKED 判死 |
| `core/files.c` | 仅失败时打印 CFL-FAIL/OFL-FAIL 诊断 | 关卡文件生命周期排障 |
| `core/weapon.c` / `core/botl.c` | 野指针守卫 | 早期崩溃兜底 |

## 七、构建排障速查

| 现象 | 处理 |
|---|---|
| 链接报 `unexpected undefined symbol rename` 等 | libc.bc 内部需要某 POSIX 符号：在 `tcm_fs.c` 文件尾强符号包装区补函数体 |
| 改了代码但镜像行为不变 | 检查编辑器是否回滚了补丁文件(补丁见上表)，重新配置后再构建 |
| Debug 配置构建失败 | 只用 Release(sysroot 无 debug 版) |
| 宿主需要数据文件 | 从 `asset/nethack/dat/` 目录运行 |
| 想调试设备文件层逻辑 | 用宿主 RAM-fs 版，gdb 打完整调用栈 |
| 查看 .tcm 符号表 | 工具链无 nm/readelf；可用 LLVM 的 `llvm-nm`/`llvm-objdump` 解析 |
